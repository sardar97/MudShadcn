# MudShadcn

A NuGet package that makes MudBlazor look like shadcn/ui. It is a `MudTheme` plus one stylesheet,
and a small stylesheet for each of shadcn's other styles that the provider links when a theme asks
for it; it adds no components of its own and must never wrap, fork or replace MudBlazor's.

**Committing is allowed** when a task is finished or Sardar asks for it: on the current branch, with
the configured git identity, in the style of `git log` (`fix(css): Subject`). **Never add a
`Co-Authored-By` or "Generated with" line to a commit message.** Never push, tag, merge, rebase,
amend or force anything: Sardar does those, and the releases (`RELEASE.md`). The one exception to
committing is a MudBlazor update, which `UPDATING.md` leaves in the working tree for review.

## Layout

- `src/MudShadcn/` — the package (Razor class library, `net10.0`, MudBlazor 9.12.0).
  - `MudShadcnTheme.cs` — builds a theme from `ShadcnThemeOptions`: typography, radius, elevation,
    and the palettes, which `FillPalette` computes from the tokens (`OklchColor.cs` converts
    OKLCH to the hex MudBlazor needs).
  - `ShadcnThemeOptions.cs` — what shadcn/create offers, under shadcn's names: the options record
    and the enums (`ShadcnStyle`, `ShadcnBaseColor`, `ShadcnColor`, `ShadcnRadius`, the menu options,
    `ShadcnIconLibrary`).
  - `ShadcnTheme.cs` — the `MudTheme` subclass `MudShadcnTheme` returns. It carries what a
    `MudTheme` has no place for: the tokens, the radius, the style, the menu options, the icon library.
  - `ShadcnTokens.cs` — the default theme's OKLCH tokens, light and dark, and `Build`, which puts a
    theme's tokens together the way shadcn/create does (base colour, then theme colour, then charts).
  - `ShadcnThemeData.g.cs` — the base colours, theme colours and Tailwind grey scales. Generated by
    `tools/generate-shadcn-themes.mjs`; never edit it by hand.
  - `wwwroot/MudShadcn.css` — structural overrides and the `--shadcn-*` tokens: the New York look,
    which is the default and the base of every style. `MudShadcn.min.css` next to it is generated
    from it on build and git-ignored.
  - `wwwroot/styles/` — one stylesheet per style (`vega.css` … `rhea.css`) and per menu option
    (`menu-bold.css`, `menu-inverted.css`, `menu-translucent.css`). Each holds only what differs
    from `MudShadcn.css` and is linked after it. Their `.min.css` files are generated too. See
    "Styles" below. The five `icons-<library>.css` files there are the icon libraries: generated by
    `tools/generate-shadcn-icons.mjs`, never edited by hand ("Icon libraries" below).
  - `MudShadcnProvider.razor` — wraps `MudThemeProvider` + popover/dialog/snackbar providers,
    emits the theme's `--shadcn-*` tokens for the active mode and links the theme's stylesheets
    (`ShadcnTheme.StyleSheets`: the style, then the menu options, then the icon library). `Enabled="false"` gives MudBlazor's own look:
    it finds the page's `<link>` to the stylesheet (by `_content/MudShadcn/MudShadcn` in the href, or
    a `data-mudshadcn` attribute) and sets `sheet.disabled` through JS interop. Both sample apps
    have a dropdown for it in the top bar.
  - `ServiceCollectionExtensions.cs` — `AddMudShadcn()`.
  - `icon.png` — the package icon (from `docs/images/logo.svg`).
- `samples/MudShadcn.TestApp/` — Blazor Server, global InteractiveServer. One page per component
  category: the quick way to see whether a change worked.
- `samples/MudShadcn.Showcase/` — Blazor WebAssembly, the public showcase (Cloudflare Pages builds
  it from the `docs` branch). A port of mudblazor.com's component docs: same menu and order, every
  MudBlazor docs example, run against MudShadcn. Use it to check a change against every variant
  MudBlazor documents.
  - `Pages/Components/` is MudBlazor's docs, copied by `sync-mudblazor-docs.sh`. Do not edit it by
    hand; re-run the script (its comments list the few edits it makes).
  - `Docs/` re-implements the MudBlazor.Docs page components the ported pages use, with the same
    names and parameters. A missing parameter only fails at runtime, when the page renders.
  - `wwwroot/css/showcase.css` styles the site's chrome only, never a component inside an example.
  - `Services/Changelog.cs` renders `CHANGELOG.md` (embedded at build time) on `/releases`.
  - **A page or tab that is new gets a "New" badge** in the nav drawer and the top bar:
    `<NewBadge AddedAfter="1.1" />` after its name (`Layout/NewBadge.razor`), with the newest
    released version at the time of adding it. It shows until the version after the one the page
    ships in, read from the changelog's release headings, so a release needs no step for it.
  - `Services/ShowcaseTheme.cs` holds the visitor's design (`ShowcaseDesign`: the look and every
    Theme Generator choice) for the whole site, saved in localStorage and readable from the address.
    `Pages/Customization/ThemeGeneratorPage.razor` is the Theme Generator: shadcn/create's options,
    a preview of stock components and the code to paste (`Services/ThemeCode.cs`).
  - `ShowcaseTheme.RightToLeft` is the site's direction: both layouts wrap everything, the
    provider included, in a `MudRTLProvider`, and the top bar has the switch (as mudblazor.com's
    has). `Pages/Customization/RtlLanguagesPage.razor` is the page about it. The site's own CSS
    uses logical properties (`inset-inline-end`, `border-inline-start`) so the chrome mirrors.
  - `wwwroot/` also holds what search engines and AI tools read: `robots.txt`, `sitemap.xml`
    (generated by `generate-sitemap.sh`, which the sync script runs), `llms.txt`, `skill.md`
    (also packed into the nupkg as `docs/skill.md`) and `og-image.png`. `/llms-full.txt` is the
    root `README.md`, linked in by the csproj.
  - `README.md` covers publishing, hosting and the Cloudflare Pages deploy.
- `README.md` — the GitHub page and the nuget.org page (it is packed into the nupkg), so every link
  and image in it is an absolute URL. `docs/images/` holds its logo and screenshots.
- `CHANGELOG.md` — Keep a Changelog. New changes go under `## [Unreleased]`; the release workflow
  and the showcase's Releases page both read it.
- `RELEASE.md` — how a release and a site deploy happen. Sardar runs them.
- `UPDATING.md` — procedure for moving to a new MudBlazor version. Follow it when asked to update.
- `tools/verify-mudblazor.sh` — checks the stylesheets' assumptions about MudBlazor (below).
- `tools/generate-shadcn-themes.mjs` — writes `ShadcnThemeData.g.cs` from shadcn's `themes.ts` and
  Tailwind's `theme.css`. Run it when shadcn changes a colour theme (`UPDATING.md`).
- `tools/generate-shadcn-icons.mjs` — writes `wwwroot/styles/icons-*.css` from MudBlazor's icons
  (its source on GitHub, at the referenced version) and the five icon libraries' npm packages (on
  jsDelivr, at the versions pinned in the tool). Run it after a MudBlazor update and after changing
  its `ICONS` table (`UPDATING.md`).
- `tools/test-package.sh` — packs MudShadcn into a temporary feed, points a copy of the test app at
  the package and checks that it starts and serves both stylesheets ("Packaging" below).
- `tools/smoke-test.mjs` — serves a published showcase and loads every URL of its sitemap in
  Chromium (Playwright), failing on a script error, Blazor's error bar or the Not found page.
- `.github/workflows/ci.yml` — builds with warnings as errors, runs the verify script, packs, tests
  the package, publishes the showcase and smoke-tests it, on every push and pull request. `publish.yml` packs and pushes to NuGet
  and creates the GitHub Release when a `v*` tag is pushed. `build.sh` is what Cloudflare Pages runs
  to build the showcase from the `docs` branch.

## Commands

```bash
dotnet build MudShadcn.sln                                              # must be 0 warnings, 0 errors
dotnet run --project samples/MudShadcn.TestApp --launch-profile http    # http://localhost:5152
dotnet run --project samples/MudShadcn.Showcase --launch-profile http   # http://localhost:5153
dotnet publish samples/MudShadcn.Showcase -c Release -o <scratchpad>/site   # static site, trimmed
tools/verify-mudblazor.sh                                               # stylesheet vs MudBlazor
tools/test-package.sh                                                   # the package, as a consumer gets it
node tools/smoke-test.mjs <scratchpad>/site/wwwroot                     # every page of the published showcase
```

The smoke test needs the `playwright` npm package where Node can resolve it from `tools/` (CI
installs it at the repository root without saving it; do not add a `package.json` for it) and a
Chromium: Playwright's own, or an installed Chrome with `SMOKE_BROWSER_CHANNEL=chrome`.

`MudShadcn.css` and the style sheets are served straight from `src/` in development (in both apps),
so CSS edits only need a browser reload. Both apps take a design from the address, which is how to
open (or screenshot) a page in a style: `?style=nova&base=zinc&theme=blue&chart=blue&radius=small&accent=bold&menu=inverted&icons=lucide&mode=dark`
(`look=mudblazor` for MudBlazor's own look; the showcase also takes `font=`, `heading=` and `dir=rtl`). `.razor` and `.cs` edits need a rebuild and restart. There are no tests;
verification is visual, in both light and dark mode. Both apps start in the OS colour scheme; the
showcase remembers an explicit choice in localStorage.

## Rules that are easy to break

- **The test app and the showcase must not reference MudBlazor.** They get it transitively through
  MudShadcn, and that is the proof the package works as a single reference. Do not add
  `PrivateAssets` to the MudBlazor `PackageReference` in the library either.
- **Do not set `--mud-palette-*`, `--mud-elevation-*`, `--mud-typography-*` or
  `--mud-default-borderradius` in the stylesheet.** `MudThemeProvider` writes them into an inline
  `<style>` in the body, which beats any stylesheet. They are set in `MudShadcnTheme.cs`.
- **In the stylesheet, read colours from `--mud-palette-*`** wherever a mapping exists, so dark
  mode and consumer palette changes flow through. Use `--shadcn-*` only for what MudBlazor has no
  slot for: ring, input background, destructive background, radius scale, shadows.
- **The default theme's tokens live in two places that must agree:** `ShadcnTokens.cs` and the
  `:root` block of `MudShadcn.css` (light values, the no-provider fallback). The palettes are no
  longer written out: `MudShadcnTheme.FillPalette` computes them from the tokens, and the other
  themes' tokens are generated (`ShadcnThemeData.g.cs`).
- **The default theme must not change.** `MudShadcnTheme.Create()` has to give the same palettes,
  typography, layout properties and tokens as before a change to the theme code: dump them before
  and after (reflection over the theme's properties is enough) and diff.
- **Take values from the source, not from memory.** shadcn tokens from `theming.mdx` and the
  `new-york-v4` component source in the shadcn-ui/ui repo; shadows and type scale from Tailwind's
  `theme.css`. URLs are in `UPDATING.md`. Put the Tailwind utility in a trailing comment
  (`/* h-9 px-4 */`) the way the file already does.

## Writing overrides

Overrides win by load order, so a selector needs specificity equal to or higher than MudBlazor's
rule. Look the rule up before writing one; do not guess class names.

```bash
# one rule per line, greppable
curl -sL https://api.nuget.org/v3-flatcontainer/mudblazor/9.12.0/mudblazor.9.12.0.nupkg -o mud.nupkg
unzip -o -q mud.nupkg 'staticwebassets/MudBlazor.min.css' -d mud
tr '}' '\n' < mud/staticwebassets/MudBlazor.min.css > rules.txt
grep -E '^\.mud-card-header' rules.txt
```

Do this in the scratchpad, not the repo. Things already learned the hard way:

- MudBlazor 9 adds modifier classes that raise specificity: `.mud-card-header.mud-card-header-padding`,
  `.mud-expand-panel-header-gutters`, `.mud-list.mud-list-padding`. A bare `.mud-card-header` loses.
- The date picker is a wrapping flex row that breaks after seven days only because each cell has a
  40px pitch. Keep day width + horizontal margins at 40px.
- Some values are inline styles from component parameters (`MudTabs.MinimumTabWidth`, 160px).
  Do not fight those with `!important`; document the parameter instead.
- Some classes exist only in markup, not in MudBlazor's CSS (`.mud-chip-color-default`,
  `.mud-picker-paper`, `.mud-snackbar-action-button`, …). Confirm those against rendered HTML.
- Outlined input labels are pinned above the field and the legend notch is hidden. Anything that
  touches `.mud-input-label-outlined` or `.mud-input-control` margins has to keep that working,
  including `Margin.Dense`.
- A MudBlazor rule written for one component reaches the buttons of whatever sits inside it: the
  button group's icon size, `-1px` margin and squared corners also hit the close button of a chip
  in the group. And MudShadcn's own `.mud-button` rule (`height: 36px; flex-shrink: 0`) applies to
  every MudButton MudBlazor uses internally, such as the numeric field's two spin buttons, which
  have to share the input's height. Check those when touching either.
- The date range picker draws its preview from two numbers, not from classes: `--selected-day` on
  `.mud-picker-calendar-content` (the day last pointed at or picked) and `--day-id` on every day.
  The first pick (`.mud-range-selection-anchor`) follows them too, because the other day can be in
  another month's `.mud-picker-calendar` and a touch screen has no `:hover`. Adjacent-month days
  are hidden by default (`.mud-hidden`), so every month has band ends next to hidden days.
- Charts colour series with SVG `fill`/`stroke` attributes from `ChartOptions.ChartPalette`. The
  charts section maps MudBlazor's default palette, by attribute value, to `--shadcn-chart-*`;
  palettes a consumer sets are left alone. If MudBlazor changes `DefaultChartOptions.ChartPalette`
  or the heat map's shade logic, those selectors silently stop matching. The stacked bar rounding
  goes further and relies on the palette's order and on MudBlazor drawing the segments stack by
  stack in series order; the verify script renders the charts to check that.

After CSS changes, run `tools/verify-mudblazor.sh`: it checks the classes, variables, chart colours,
chart markup and icon paths the stylesheet relies on against the referenced MudBlazor (step 3 of
`UPDATING.md`), the classes and variables of every stylesheet in `wwwroot/styles`, and every
selector of the icon libraries' stylesheets against all of MudBlazor's icons.

## Styles

shadcn's eight newer styles (Vega, Nova, Maia, Lyra, Mira, Luma, Sera, Rhea) change the geometry of
every component. `MudShadcn.css` is the New York look, written from shadcn's `new-york-v4`
components; each other style is `wwwroot/styles/<name>.css`, written from shadcn's
`apps/v4/registry/styles/style-<name>.css` (one `.cn-*` class per rule, as Tailwind utilities).

- **A style file holds only what differs from `MudShadcn.css`** and is linked after it, so a rule
  wins over the base rule with the same selector. Copy the base rule's selector exactly; if the base
  declaration has `!important`, the override needs it too. Only one style is loaded at a time, so
  every style stands on its own against the base, not on another style.
- **Every block names the `.cn-*` rule it comes from** in a comment before it, and every
  declaration keeps its Tailwind utility in a trailing comment, as in the base. That comment is the
  map from shadcn's source to MudBlazor's selectors: to update a style, diff shadcn's file and
  follow the names.
- **A fix in `MudShadcn.css` may be needed in the styles too.** A style that overrides the same
  property of the same selector hides the fix. Search `wwwroot/styles` for the selector.
- **Corners go through the radius scale** (`--shadcn-radius-sm` … `-4xl`), so the theme's radius
  option works in every style. The square styles (Lyra, Sera) set the scale to zero, and
  `--mud-default-borderradius` with it under `:root:root`, which outranks the inline `:root` block
  `MudThemeProvider` writes. That is the one `--mud-*` variable a style may set.
- **Colours as in the base:** `--mud-palette-*` where MudBlazor has a slot, `--shadcn-*` otherwise,
  never a literal. A colour that differs per mode (`dark:` variants) is `light-dark(light, dark)`,
  which follows the `color-scheme` the provider sets.
- **A style does not choose the font family** (that is the theme's `FontFamily`). It does set
  sizes, weights, `uppercase` and letter-spacing.
- **Dependent geometry.** A changed size moves everything positioned from it: an input's height
  also places its label, adornments and the numeric field's spin buttons; a calendar day's size
  sets the 40px pitch and the calendar's width; button padding is repeated in the outlined, icon,
  group and toggle rules.
- **The menu options are stylesheets too,** linked after the style: `menu-bold.css` paints the
  highlighted menu item in the primary colour, `menu-inverted.css` redefines the tokens and palette
  slots on the menu's popover from the `--shadcn-inverted-*` set the provider emits (the one place
  `--mud-palette-*` is set in a stylesheet: on an element, not on `:root`), `menu-translucent.css`
  adds the blur.
- **Check a style in both apps, light and dark,** with `?style=<name>` in the address, against the
  same page without it. There are nine looks now: a change to a shared selector needs a look at each.

## Icon libraries

`ShadcnThemeOptions.IconLibrary` (shadcn/create's Lucide, Tabler Icons, HugeIcons, Phosphor Icons,
Remix Icon; `null`, the default, is MudBlazor's Material icons) links `styles/icons-<library>.css`
after the style and the menu options. `?icons=tabler` in either app's address shows one.

- **A sheet redraws the Material icons MudBlazor's components use by default,** not the whole
  Material set. In MudBlazor an icon is a string of SVG paths, so a selector matches the `<svg>`
  MudIcon renders by its path data (`svg.mud-icon-root:has(> path[d="…"])`) and draws the library's
  icon as a `mask` over `currentColor`, at the icon's own size. That is global on purpose: the same
  Material icon in an application's markup is redrawn too, any other icon is not.
- **The sheets are generated.** The `ICONS` table in `tools/generate-shadcn-icons.mjs` has a row per
  icon: the Material names, then the icon in each library, shadcn's own choice where its components
  have one. Change the table and run the tool; never edit a sheet.
- **A selector has to match the icons it names and no other** (Material's `ZoomIn` is `Search`
  with one more path, which is why every selector also rules out an extra path). The verify script
  checks that against every icon MudBlazor ships.
- **The checkbox and radio icons are not in the table:** `MudShadcn.css` draws those as controls.
  The four glyphs it draws itself (check, dash, the select's arrows) are `--shadcn-icon-*`
  variables in its `:root` block, Lucide's by default, and a library's sheet sets its own.
- **Licences:** the icons are other people's work (`THIRD-PARTY-NOTICES.md`). Read a package's
  licence file before taking a newer version: Remix Icon is pinned at 4.8.0, the last one under
  Apache-2.0, because later versions restrict redistribution.

## MudBlazor 9 API notes

Differences from older MudBlazor that have already caused build errors here:

- `MudFileUpload` uses `<CustomContent>` with `context.OpenFilePickerAsync`, not `ActivatorContent`.
- `MudSelect` multi-select binds `IReadOnlyCollection<T>`, not `IEnumerable<T>`.
- `IDialogService.ShowAsync<T>(null, options)` is ambiguous; use the overload without a title.
- `MudTabs` panel class parameter is `TabPanelsClass`.
- Nested menus are a `<MudMenu>` inside a `<MudMenu>`, not nested `MudMenuItem`s.
- `MudGlobal` no longer has per-component defaults, so variants cannot be defaulted globally.
- The `MUD0002` analyzer flags unknown parameters; treat it as an error.

## Packaging

`dotnet pack src/MudShadcn -c Release -o <scratchpad>/feed`. To test the real package, run
`tools/test-package.sh` (or `tools/test-package.sh <folder with the .nupkg>`): in a temporary
folder it copies the test app, swaps its `ProjectReference` for a `PackageReference` restored from
a local feed, publishes and starts it, and checks that the page renders and that
`_content/MudBlazor/MudBlazor.min.css` and `_content/MudShadcn/MudShadcn.min.css` are served. CI and
the publish workflow run it on the package they packed. Never pack into the repo and never publish
to nuget.org; Sardar does that.
